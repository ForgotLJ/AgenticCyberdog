## 8 · 2026-10-21 18:53:31 · 助手

**有。对你们的 Agent4CyberDog，我最推荐先看 VLN-CE-Isaac／NaVILA、VLN-PE 和 RobotWorld。** 它们分别对应“语言指令控制机器狗”“考虑四足身体的导航评测”“通用 agent 使用机器人”。

我检索了 papers.cool，并核对了 arXiv 原文和官方仓库。截至 **2026-10-21**，下面这些最值得关注；本次没有实际运行仿真或真机。

| Benchmark | 能评价什么 | 对你们的价值与限制 |
|---|---|---|
| **[VLN-CE-Isaac／NaVILA](https://github.com/yang-zj1026/VLN-CE-Isaac)**，2024–2025 | 根据语言完成导航，包含真实关节运动、碰撞和障碍；评价成功率、路径效率、终点误差 | **建议最先尝试。** 有 Go2、本体运动策略、场景数据、模型权重入口和评测脚本。迁移 CyberDog 仍需适配运动与感知接口 |
| **[VLN-PE](https://crystalsixone.github.io/vln_pe.github.io/)**，2025 | 语言导航在不同身体、光照和场景中的表现；额外评价**跌倒率、卡住率** | **非常符合机器狗平台。** 支持四足、人形、轮式机器人，[代码在 InternNav](https://github.com/InternRobotics/InternNav)。适合研究“仿真里会导航，换成真实身体为什么失败” |
| **[RobotWorld](https://github.com/robotworldai/robotworld)**，2026-10 | Agent 根据观察调用机器人接口，完成任务并接受独立成功检查 | **最贴近 agentic benchmarking。** 84 个跨本体任务，含 Go2 抗推恢复、ANYmal 崎岖地形等；但当前发布版本仍有测试和仿真验证缺口，复现成本较高 |
| **[ObjectNav／VLN-CE](https://github.com/jacobkrantz/VLN-CE)**，基于 Habitat | “找到椅子”“出门右转走到桌前”；评价成功率、路径效率、路线符合程度 | 适合先测 agent 的视觉理解、搜索和规划。常用导航配置不模拟真实四足步态，因此分数不能代表机器狗的运动能力 |
| **[Barkour](https://sites.google.com/view/barkour)**，2023 | 绕杆、爬坡、跳跃等敏捷运动；按耗时和障碍完成情况计分 | **适合评价底层运动控制。** 有公开赛道资产和评分脚本。虽然较早，但协议很具体；若只让 agent 调用原厂走路接口，成绩会很大程度受原厂控制器影响 |
| **[MQE](https://github.com/ziyanx02/multiagent-quadruped-environment)**，2024 | 推箱、足球、过桥、多狗合作与对抗 | 适合后续发展推球、交互任务。提供预训练行走策略，但主要面向多智能体强化学习，接入语言 agent 需要额外封装 |

**如果只能先选一个，我建议从 NaVILA 的 VLN-CE-Isaac 开始。**

它的优势是复现材料比较具体，而且确实围绕机器狗展开。[论文](https://arxiv.org/abs/2412.04453)中，同一 Go2 仿真设置下：

- 使用视觉底层运动策略：成功率 **50.2%**，路径效率指标 SPL **45.5%**。
- 使用仅本体感知的运动策略：成功率 **36.2%**，SPL **33.3%**。

这说明一个很实际的问题：**即使高层模型相同，底层运动策略也能明显改变最终成绩。** 你们比较不同 agent 时，应固定底层控制器。仓库还固定了较旧的 Isaac Sim／Isaac Lab 版本；文档要求本地运行其 VLA 评测至少有 24 GB 显存，也支持把模型服务放到另一台机器。

**关于聊天里提到的 Astra，已有证据支持“值得测导航”，但还不能据此认为它能可靠实时控制真狗。**

[这篇 2026 年的系统评测](https://arxiv.org/abs/2609.38537)报告：

- 英语 RxR 指令导航：**46/50 成功，92%**。
- HM3D 找物：**41/50 成功，82%**，但 SPL 只有 **43.69%**，说明经常绕路。
- 同一运动障碍赛道的 **5 次连续适应尝试均未到达目标**。

前两项是固定小样本、特定动作和成功阈值下的结果，不能直接当作官方完整榜单 SOTA；后五次尝试也不是独立重复试验。尤其需要注意，运动实验在模型推理时暂停了仿真，不能直接推导真实时间下的控制能力。

群里提到的 **[RCI_quadruped_robot_navigation](https://github.com/RCILab/RCI_quadruped_robot_navigation)** 可以作为 Gazebo／Nav2 环境基础，但我查到的 README 没有完整的固定任务集、统一评分协议和基线成绩表，因此还需要你们补上评测部分。

我的建议是：**先用现成 benchmark 比较模型，再做少量 CyberDog 真机迁移任务。** 真机第一版可覆盖定距转向、按语言经过地标、寻找物体、受阻后绕行、推球到目标区域；统一记录成功率、位置误差、碰撞、人工接管、耗时和模型调用成本，并用外部视频或标记判定成功。这样更容易判断究竟是 agent 不会规划，还是运动执行出了问题。

## 10 · 2026-10-21 18:58:18 · 助手

下面这份清单按 **Agent4CyberDog 的适用程度**整理。“对应部分”指你们值得复用的具体任务或评测模块。

| Benchmark | 适合机器狗的具体部分 | 主要评价指标 | 优势 | 局限与适配工作 |
|---|---|---|---|---|
| **[VLN-CE-Isaac／NaVILA](https://github.com/yang-zj1026/VLN-CE-Isaac)** | **Go2 语言导航**：根据指令前进、转弯、穿过房间、到达指定位置 | 成功率 SR、路径效率 SPL、终点误差 NE | 与机器狗任务直接相关；有场景数据、预训练运动策略和评测脚本；有真机实验参考 | 依赖特定版本 Isaac Sim／Isaac Lab；Go2 策略不能直接用于 CyberDog，需要适配本体、相机和运动接口 |
| **[VLN-PE](https://crystalsixone.github.io/vln_pe.github.io/)** | **考虑真实身体的语言导航**：四足在不同场景、光照和视角下完成路线任务 | SR、SPL、NE，以及**跌倒率、卡住率** | 能暴露普通导航仿真忽略的身体约束；适合研究导航模型到机器狗的迁移问题 | 平台和数据准备较复杂；现成四足配置不是 CyberDog；需要区分导航失败与底层运动失败 |
| **[RobotWorld](https://github.com/robotworldai/robotworld)** | **四足任务子集**：Go2 抗推恢复、ANYmal 崎岖地形、A1 前腿倒立；另可借鉴通用 agent 评测框架 | 任务成功、交互预算、执行记录和资源消耗 | 最贴近“通用 agent 使用机器人”；动作接口和成功检查明确，适合分析失败过程 | 部分任务是关节级控制，与调用原厂走路接口差异很大；推理时暂停仿真；当前公开版本仍有复现验证缺口 |
| **[Habitat ObjectNav](https://github.com/facebookresearch/habitat-lab)** | **自主找物**：给出“椅子／沙发”等目标类别，让机器狗搜索并接近 | SR、SPL、搜索路径与步数 | 任务定义清楚，适合比较视觉识别、探索、记忆和停止决策；可先固定运动层评测 agent | 常用配置不模拟四足步态和接触动力学；仿真成功不代表真狗能通过同一路线；迁移需处理相机高度和定位误差 |
| **[VLN-CE：R2R／RxR](https://github.com/jacobkrantz/VLN-CE)** | **语言路线执行**：例如“出门右转，经过沙发，停在桌子旁” | SR、SPL、NE、路线符合程度 nDTW 等 | 指令、场景、评测协议较成熟；适合测语言理解、空间记忆和多步骤导航 | 对真实运动执行的简化较多；不能充分评价跌倒、打滑和身体碰撞；原仓库依赖较旧 |
| **[Barkour](https://sites.google.com/view/barkour)** | **底层敏捷运动**：绕杆、爬坡、跳跃、上下平台 | 赛道完成时间、障碍完成情况、Barkour score | 专门面向四足运动；有明确评分规则和公开赛道资产，适合比较运动控制器 | 更偏运动控制与本体性能；若你们主要研究高层 agent，区分度可能有限；修改赛道后不能直接与官方成绩比较 |
| **[MQE](https://github.com/ziyanx02/multiagent-quadruped-environment)** | **物体交互与多狗协作**：推箱、足球、过桥、合作与对抗 | 按任务统计成功、回报或胜负 | 有多种四足交互任务和预训练行走策略；适合扩展推球、推箱及多狗任务 | 主要面向多智能体强化学习；接入视觉语言 agent 需要封装观察和动作；依赖较旧的 Isaac Gym 栈 |

**适合关注，但暂不作为第一项复现：**

| 条目 | 对应部分 | 优势 | 当前不足 |
|---|---|---|---|
| **[DPed-VLN](https://github.com/tju-dhj/DPedVLN)** | 动态行人环境中的语言导航、避让与安全距离 | 同时评价导航效率和社会安全，适合以后研究机器狗在人群中行动 | 本轮核查时数据已发布，评测代码仍待发布；也不是四足动力学评测 |
| **[RCI quadruped navigation](https://github.com/RCILab/RCI_quadruped_robot_navigation)** | Go2 等机器狗的 Gazebo／Nav2 导航环境 | 可作为搭建仿真、定位和导航系统的基础 | 属于环境与工程集成；本轮查看的 README 没有完整固定任务集、评分协议和基线成绩，需自行补成 benchmark |

**针对你们项目，建议这样选：**

- **先跑通“语言控制机器狗”**：选 **VLN-CE-Isaac／NaVILA**。
- **研究真实身体带来的导航失败**：选 **VLN-PE**。
- **研究 agent 的接口使用、反馈纠错和任务完成能力**：参考 **RobotWorld** 的评测设计。
- **研究推球、推箱或多狗协作**：参考 **MQE**。
- **研究步态、越障、抗扰等底层控制**：选 **Barkour**。

比较不同 agent 时，尽量固定机器人、传感器和底层控制器；否则最终分数很难区分是模型能力提升，还是运动系统更强。以上属于资料与代码核查结论，尚未在 CyberDog 上实测。

| **[unitree_mujoco](https://github.com/unitreerobotics/unitree_mujoco)** | **宇树官方**；明确提供 Go2 模型、场景及 C++／Python／ROS 2 示例 | 相对轻量；直接对接 SDK2／DDS；适合关节控制、控制器调试和仿真到真机的接口验证 | **主要支持低层控制**。默认示例是站立等动作，需要另外接行走控制器 |
| **[unitree_rl_lab](https://github.com/unitreerobotics/unitree_rl_lab)** | **宇树官方**；有 `Unitree-Go2-Velocity` 训练任务及 Go2 部署代码 | 官方的 Isaac Lab 强化学习路线；适合训练步态、速度跟踪，随后在 MuJoCo 中验证 | 环境较重；Go2 部署配置指向训练结果目录，本轮未找到仓库自带的 Go2 预训练权重包 |
| **[Isaac Lab](https://github.com/isaac-sim/IsaacLab)** | **NVIDIA 框架官方支持**，非宇树维护；源码包含 Go2 平地、粗糙地形速度跟踪环境 | 训练生态完整，适合并行实验、地形与传感器扩展 | 需要准备控制策略和任务；不包含 Go2 原厂完整运动软件，版本兼容需单独确认 |
| **[rl_sar](https://github.com/fan-ziqi/rl_sar)** | **社区项目**；维护者标注 Go2 支持 Gazebo、MuJoCo、真机；仓库有 Go2 策略文件和部署代码 | **最适合快速获得“会走的仿真 Go2”**；提供预训练策略，ROS／Gazebo 路径支持 `/cmd_vel` | 使用自己的运动策略，响应不一定等同原厂；优先使用当前 C++ 版本，Python 版暂停维护；Gazebo 路线使用已结束维护的 Classic |

**对你们的 agent 项目，最重要的区别是：官方仿真支持，不等于原厂高层 API 已完整仿真。**

`unitree_mujoco` 的 README 明确写着：

> Current version only supports low-level development.

它支持 `LowCmd`、`LowState`、`SportModeState` 等消息，但**不能据此认为真机上的 `SportClient.Move()`、避障服务和相机取流都能原样使用**。尤其是 `SportModeState` 是状态数据，不代表仿真中已经运行原厂行走服务。

我的建议是：

- **先让 agent 控制虚拟 Go2 前进、转向、停止：优先考察 `rl_sar`。** 已有行走策略，省去自己训练步态的步骤；MuJoCo 路径的 agent 接口仍需确认或适配。
- **希望尽量沿用宇树 SDK2：选择 `unitree_mujoco`＋Go2 行走控制器。**
- **希望训练或改进运动策略：选择 `unitree_rl_lab`。**
- **希望直接评测语言导航：继续考虑此前的 [VLN-CE-Isaac／NaVILA](https://github.com/yang-zj1026/VLN-CE-Isaac)**，它额外提供了场景与评测任务。

另外两个容易踩坑的地方：

1. **`unitree_sim_isaaclab` 和 `unitree_rl_lab` 是不同项目。** 前者当前主要面向 G1／H1-2，本轮没有核实到 Go2 专用实现；查 Go2 应优先看后者。
2. **不要直接混用最新版本。** Isaac Lab 3.0 已发布，但宇树 RL Lab 当前 README 仍标注 Isaac Sim 5.1.0／Isaac Lab 2.3.0，应先按项目声明的版本复现。

本次是在线资料与源码核查；社区的真机支持来自维护者说明，我尚未在你们设备上运行验证。完整对比已保存到 [Go2 仿真环境核查.md](D:/Project/AgenticCyberDog/docs/go2-simulation-environments-2026-10-24.md)。
